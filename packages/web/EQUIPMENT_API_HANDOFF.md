# 器材展示接口对接（2026-09-24）

本次修改位于 `equipment-manager` 工作仓库，不是 `equipment-manager-develop` 下载副本。
按下载副本中实际路由实现对接，没有覆盖或修改后端、数据库和旧演示数据。

## 已接入

- `#/equipment`：Axios 请求 `/api/equipments`，参数为 `page`、`pageSize`、`name`、`category_id`。
- 分类：`GET /api/categories`，采用实际返回的扁平数组，不按文档猜测树结构。
- 详情：`GET /api/equipments/:id`，使用后端数字 ID。
- 展示名称、介绍、分类、总库存、可用库存、停用状态。
- 筛选重置页码、空列表、失败重试、超时提示、分类独立重试、取消过期请求、手机布局。

## 演示与真实数据边界

`#/demo/equipment` 保留旧演示借用，工作台的虚构推荐器材也跳到此处。
工作台统计、账号、借还、耗材和管理页面仍使用浏览器演示数据。
当前登录入口仍是演示入口；它不提供真实后端授权，也不会发送虚构 Token。
真实设备页不提供借用提交，不把服务器数据写入演示台账。
后端新增认证后需要另行对接真实会话，不能以本地路由检查替代后端权限校验。

## 启动与配置

在工作仓库根目录运行 `pnpm --filter web dev`，使用终端显示的地址。
进入“成员体验”，再进入“设备中心”。

开发代理默认转发到 `http://127.0.0.1:3000`。
需要启动提供新版器材路由的后端，旧工作仓库的健康检查服务不满足要求。
如后端地址不同，在 `packages/web/.env.local` 设置 `API_PROXY_TARGET`，然后重启前端。
此变量只用于开发代理；生产环境必须配置同源 `/api` 反向代理。
数据库连接字符串只属于后端，不得放进前端环境变量或代码。
