# 初版前端交接

## 启动

在仓库根目录执行 `pnpm --filter web dev --host 127.0.0.1`，打开终端显示的网址。默认端口为 5173；若占用，Vite 会选择下一可用端口。构建检查：`pnpm --filter web build`。

工作分支：`feature/frontend-mvp`。前端代码在 `packages/web/src`，未修改后端、共享数据库或根依赖配置。

## 当前交付

这是完整的第一版前端演示流程，**不是已联调可上线的系统**。后端目前只有健康检查，未提供业务接口，因此业务动作在 Pinia store 中模拟，数据存放在浏览器 localStorage，登录会话存放在 sessionStorage。固定演示入口无需密码，绝不能当作正式登录发布。注册账号只供演示，密码通过带随机盐的 PBKDF2 派生，不保存明文；这也不能替代服务端认证。

- 登录、注册、退出、个人资料、修改测试账号密码。
- 工作台、可用设备、库存预警、个人借用与通知概览。
- 设备搜索、分类 / 状态过滤、分页、详情及借出人和预计归还时间。
- 借用、归还、我的借用和管理人员的借用记录。
- 耗材搜索、领用、库存扣减与领用记录。
- 成员申请、通过 / 驳回、审批结果通知和管理人员直接设置成员身份。
- 设备 / 耗材新增与编辑；入库 / 盘点通过变动记录调整库存。
- 固定角色访问控制、用户角色与部门归属调整、通知已读和操作日志。
- 桌面与移动端布局、移动抽屉导航、空数据状态、表单校验和失败提示。

## 演示方式

登录页有成员、非成员、管理员三个入口。可以先以非成员身份提交申请，退出后使用管理员入口审批，再退出并以原身份进入查看结果。审批会把“非成员体验”对应账号实际改为成员，这属于预期行为。若需全新非成员，可注册虚构账号。

演示数据键是 `ipa-equipment-demo-v1`，会话键是 `ipa-equipment-session-v1`。用浏览器开发者工具删除这两个键后刷新可重置；不要清空该域名下其他应用的数据。数据在不同浏览器 / 域名 / 端口之间不共享，不模拟多终端并发。

## 后端联调清单（接口建议，尚未约定）

| store 动作                                 | 所需后端能力                                       |
| ------------------------------------------ | -------------------------------------------------- |
| login / register / logout / changePassword | 认证、密码哈希、会话失效、修改密码与身份确认       |
| 读取 db                                    | 分页查询设备、耗材、借用、用户、申请、通知、日志   |
| borrow / returnLoan                        | 校验成员身份、可借状态、记录借还；事务防止重复借出 |
| moveStock                                  | 事务扣库存 / 入库 / 盘点，禁止负库存，保存流水     |
| apply / review / updateUser                | 成员申请审批、角色与部门调整、操作授权             |
| saveAsset / saveMaterial                   | 台账校验、编号唯一、维护记录                       |
| markRead / updateProfile                   | 当前用户通知和资料更新                             |

正式接入时，删除演示登录、移除本地认证和业务存储，使用后端返回的用户、权限和记录。不能在前端连接 PostgreSQL，也不能把数据库密码、管理员密钥放在 `VITE_` 变量中。前端菜单隐藏只负责交互，所有访问权限、数据范围和库存一致性必须由后端验证。错误时显示服务端允许暴露的提示；提交期间禁用按钮，防止重复提交。

## 需团队确认 / 不在本次实现范围

1. 草案将“审批中心”列在二期，但成员审批属于 MVP：本次已实现成员专用审批；贵重器材审批开关未开放，演示器材均按免审批流程。
2. 角色沿用草案固定列表，演示管理角色可操作全体虚构数据。部门 / 组别的数据范围、自定义权限点、独立部门维护页面需后端契约与团队确认后实现。当前可调整成员和器材的部门归属。
3. 密码找回的身份验证方案、敏感操作重新认证、真实身份校验待后端定义，不显示假的“重置成功”。
4. 工位、扫码、续借与逾期通知、报表导出、QQ 通知属于二期，未添加无效占位入口。
5. 设备图片上传接口尚未定义，当前使用图标占位。设备资料可编辑文字说明，后续接入图片资源。
6. 服务端日志留存、备份、并发锁、真正鉴权、部署与安全验收由后端配合完成。浏览器演示日志可被用户改动，不是可信审计记录。

## 验收

构建必须通过 `vue-tsc -b && vite build`。浏览器中逐一测试：成员借还、库存领用/入库/盘点、非成员拒绝借用、管理地址访问限制、申请审批、注册改密和错误密码、通知已读、刷新持久化、手机导航。真实后端接入后还需补充多用户并发、接口超时/无权限/业务冲突和生产数据隔离测试。
